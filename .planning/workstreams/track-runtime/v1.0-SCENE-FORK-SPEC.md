# v1.0 Scene Fork — Design Specification

**Status:** Draft
**Created:** 2026-04-03
**Based on:** design discussion (see ROADMAP.md v1.0)

---

## Core Abstraction

### Scene vs WorldState

```
WorldState (canonical)
├── scene_graph: Dict[scene_id, Scene]
├── focus_scope: Dict[player_id, scene_id]   # which scene a player is watching
├── scene_lifecycle: Enum[OPEN, LOCKED, RESOLVED, MERGED]
└── batch_queue: List[PendingAction]          # collected before resolution

Scene (local context)
├── id, name
├── participants: Set[player_id]              # who is in this scene
├── focus: scene_lifecycle
├── entry_trigger: TriggerSpec
├── exit_trigger: TriggerSpec
├── local_state: dict                        # scene-local vars (not canonical)
└── pending_actions: List[ActionIntent]       # batch collected for this scene
```

**Key invariant:** A player can only `belong_to` one scene at a time (no multi-scene subscription).

---

## Scene Lifecycle (separate from focus)

```
OPEN      → scene is accepting actions, can fork/merge
LOCKED    → batch collection closed, resolution in progress
RESOLVED  → consequences published, awaiting merge decision
MERGED    → scene closed, participants redirected
```

**Focus state** is orthogonal: `FOCUSED | UNFOCUSED | CROSS_CUT`. A scene can be `OPEN` but `UNFOCUSED` (backgrounded).

## Fork Mechanics

### `fork(new_scene_name, initiating_player, split_type)`

```
fork()
├── Validate: max 2 OPEN scenes across all
├── Validate: initiating_player not already in OPEN scene
├── Create new Scene with:
│   ├── participants = {initiating_player}
│   ├── lifecycle = OPEN
│   ├── entry_trigger = auto-resolve or manual
│   └── exit_trigger = auto-resolve or manual
├── DO NOT change focus automatically
└── Return (new_scene_id, fork_status)
```

**Key:** `fork()` is immediate. Focus change requires separate `switch_focus()` call.

### `switch_focus(player_id, target_scene_id)`

```
switch_focus()
├── Validate: player belongs to source scene (if any)
├── Validate: player belongs to target_scene_id
├── Update WorldState.focus_scope[player_id] = target_scene_id
└── Return (previous_scene_id, new_scene_id)
```

**Cross-cut:** When a scene is RESOLVED and player switches to another OPEN scene, a "cutaway" is triggered in the narrator. Main scene continues; player sees brief transition narrative.

## Batch Collection

### Collection Policy: "See All, Act Local"

```
Phase 1: Collection
- All OPEN scenes collect actions into scene.pending_actions
- WorldState.batch_queue accumulates ALL pending_actions across scenes
- Players can see that actions are pending in other scenes (visibility rules)

Phase 2: Lock & Resolve
- KP or auto-trigger locks scenes for resolution
- Each scene resolves its local_actions against its local_state
- WorldState updates canonical fields only

Phase 3: Publish
- Consequences assigned to owning scene/player
- Narrator produces: main scene narrative + up to 1 cross-cut/cutaway
- WorldState.scene_lifecycle updated
```

---

## Merge Mechanics

### Semi-Auto: Suggest + Confirm

```
merge_propose(scene_id, target_scene_id)
├── Validate: both scenes RESOLVED
├── Validate: participants have spatial/plot compatibility
├── Create MergeSuggestion with:
│   ├── source_scene, target_scene
│   ├── combined_summary: str
│   └── trigger: "auto" | "manual"
└── Notify participants → confirmation required

merge_confirm(merge_id)
├── If confirmed: execute merge
│   ├── Combine participant focus_scope entries
│   ├── Archive source scene (lifecycle = MERGED)
│   ├── Run exit_trigger of source, entry_trigger of target
│   └── Clear source scene from scene_graph
└── If rejected: keep both scenes open, KP decides
```

## Trigger Spec Structure

```python
class TriggerSpec:
    type: Literal["narrative", "condition", "composite"]
    # For narrative:
    narrative_text: str  # AI promptable
    # For condition:
    condition: Expression  # e.g. "SAN < threshold"
    # For composite:
    steps: List[TriggerSpec]
    operator: Literal["AND", "OR", "SEQUENCE"]
```

---

## Narrator Output Contract

For v1.0, narrator produces at most **2 narrative blocks**:

1. **Main narrative** — dominant scene resolution
2. **Cutaway** (optional, max 1) — cross-cut to background scene or player

No simultaneous parallel narrations. Cutaways are brief bridging text.

---

## Constraints (v1.0)

- Max 2 OPEN scenes at any time
- Single-player-per-scene (no shared scene in v1.0)
- No scene-to-scene dependency chains
- No automated merge; KP reviews and confirms
- Trigger specs are declarative; runtime executes but doesn't author them
