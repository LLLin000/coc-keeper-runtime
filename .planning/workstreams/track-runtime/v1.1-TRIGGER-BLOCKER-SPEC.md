# v1.1 Trigger & Blocker Runtime — Design Specification

**Status:** Draft
**Created:** 2026-04-03

---

## Core Problem

Current trigger system applies effects inline and treats blockers (clarifications, pending rolls) as side effects. Complex module behavior is hard to reason about and harder to recover.

---

## Trigger Event Entry Contract

```python
class TriggerEvent:
    trigger_id: str
    scene_id: str
    source: Literal["player_action", "time_elapsed", "condition_met", "manual"]
    predicate: TriggerSpec          # from v1.0 spec
    context: dict                   # world_state snapshot at trigger time
    status: Literal["pending", "running", "blocked", "completed", "failed"]
    checkpoint_id: str | None       # for resumption
```

---

## Reaction Classification

```python
class ReactionSpec:
    reaction_type: Literal["narrative", "mechanical", "composite"]
    priority: int                  # execution order
    conditions: List[TriggerSpec]  # pre-conditions
    effects: List[Effect]
    blockers: List[BlockerSpec]    # what can interrupt this

class Effect:
    target: Literal["scene", "player", "world"]
    field: str                     # e.g., "SAN", "scene.local_state.darkness"
    operation: Literal["set", "delta", "roll", "apply"]
    value: Any
```

---

## Blocker Checkpoints

```python
class BlockerSpec:
    blocker_type: Literal["clarification", "roll_gate", "choice", "external"]
    description: str               # human-readable for KP
    required_resolution: Any       # e.g., roll outcome, player choice
    timeout: int | None            # in turns, or None
    
    # For resumption:
    savepoint: str                 # trigger event context at block time
    resume_from: str               # step/condition to resume from
```

---

## Resumable Trigger Chains

```
TriggerChain:
    chain_id: str
    events: List[TriggerEvent]
    current_index: int
    blocked_at: BlockerSpec | None
    audit_log: List[AuditEntry]
    
    resume()
    ├── Restore savepoint
    ├── Re-evaluate blocker conditions
    └── Continue from resume_from
    
    checkpoint()
    ├── Serialize current state
    └── Store to PersistenceStore
```

---

## Audit Events

```python
class AuditEntry:
    timestamp: datetime
    trigger_chain_id: str
    event_type: Literal["trigger_fired", "blocker_raised", "blocker_resolved", "effect_applied", "chain_completed"]
    details: dict
    world_state_snapshot: str      # hash or delta for integrity
```

## v1.1 Phases

2. **Reaction classification** — formalize ReactionSpec and effect application model
3. **Blocker checkpoints** — formalize BlockerSpec, savepoint/resume semantics
4. **Resumable chains** — implement TriggerChain persistence and recovery
5. **Audit trail** — implement AuditEntry logging, integrate with PersistenceStore
